¿Qué es exactamente el PCB?

El Process Control Block (Bloque de Control de Proceso, a veces también llamado Descriptor de Proceso o Task Control Block) es la estructura de datos que usa el sistema operativo para representar a un proceso desde adentro del kernel.

Definición, en nuestras palabras

Podemos pensar al PCB como el "documento de identidad" que el sistema operativo le abre a cada proceso en el momento en que nace, y que va actualizando durante toda su vida. Es una estructura de datos (en la práctica, algo similar a un registro o un "struct") que concentra toda la información necesaria para que el sistema operativo pueda administrar, planificar y, si hace falta, pausar y reanudar ese proceso en cualquier momento.

No hay un único PCB para todo el sistema: cada proceso tiene el suyo propio. El conjunto de todos los PCB activos suele organizarse en una estructura que el sistema operativo mantiene para poder ubicarlos rápido, comúnmente llamada tabla de procesos (process table), donde cada entrada apunta (o contiene directamente) al PCB de un proceso.

¿Quién crea el PCB?

El PCB lo crea el propio núcleo del sistema operativo (kernel), específicamente el subsistema encargado de la gestión de procesos. Esto ocurre en el momento en que se solicita la creación de un nuevo proceso: por ejemplo, cuando un usuario abre una aplicación, cuando un proceso ya en ejecución crea un proceso hijo, o cuando el propio sistema operativo arranca sus servicios internos.

En términos generales (sin entrar en la implementación puntual de un SO específico), el flujo es más o menos así: el kernel recibe el pedido de creación de proceso, reserva memoria para el nuevo proceso, le asigna un identificador único, y construye su PCB completando los campos con los valores iniciales correspondientes (estado "nuevo" o "listo", puntero de programa apuntando al inicio del código, prioridad por defecto, etc.). De ese PCB nadie más que el sistema operativo se encarga: el propio proceso, ejecutándose en modo usuario, no puede leerlo ni modificarlo directamente.

¿Dónde vive el PCB en memoria?

El PCB se guarda en una zona de memoria reservada para el sistema operativo, conocida habitualmente como espacio de memoria del kernel (kernel space), que está protegida y a la que los procesos de usuario no tienen acceso directo. Esto es intencional: si cualquier proceso pudiera modificar libremente su propio PCB (por ejemplo, subirse la prioridad a mano o mentir sobre su estado), se rompería por completo la administración justa y segura de los recursos del sistema.

A grandes rasgos, podemos imaginar la memoria del sistema dividida en dos grandes zonas: una zona de espacio de usuario, donde corre el código y los datos de las aplicaciones (incluido el proceso al que pertenece cada PCB), y una zona de espacio de kernel, donde el sistema operativo guarda sus propias estructuras de control, entre ellas la tabla de procesos con todos los PCB activos. Solo el kernel, corriendo en modo privilegiado, puede leer y escribir esa zona.

💡 Para recordar

El PCB no es un archivo que el usuario pueda abrir ni algo que "se vea" en pantalla: es una estructura interna del sistema operativo, invisible para las aplicaciones, que existe únicamente mientras el proceso al que pertenece está vivo.

Un dato importante: PCB y PID no son lo mismo

Es común confundir el PCB con el PID (Process ID). El PID es apenas uno de los datos que el PCB contiene: un número que identifica de forma única al proceso mientras existe. El PCB, en cambio, es toda la estructura completa que agrupa el PID junto con muchísima más información (estado, registros, memoria, archivos abiertos, etc.), como vamos a ver en la próxima sección.
