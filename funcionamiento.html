El PCB a lo largo de la vida de un proceso

El PCB no es estático: nace con el proceso, se actualiza constantemente mientras el proceso vive y desaparece cuando el proceso termina. Veamos cada etapa.

1. Creación del PCB

  1. Se solicita crear un proceso (por ejemplo, el usuario abre un programa, o un proceso existente pide crear un hijo).
  2. El kernel reserva memoria para el nuevo proceso y le asigna un PID único que no esté en uso.
  3. El kernel construye el PCB del proceso y lo completa con valores iniciales: estado "nuevo" (o directamente "listo"), PC apuntando a la primera instrucción del programa, prioridad por defecto (o heredada del proceso padre), memoria asignada, y una lista vacía o heredada de archivos/dispositivos abiertos.
  4. El nuevo PCB se agrega a la tabla de procesos del sistema operativo y el proceso pasa a la cola de listos, esperando su turno de CPU.

2. Actualización durante el cambio de contexto

El cambio de contexto (context switch) es el mecanismo por el cual el sistema operativo le quita la CPU a un proceso para dársela a otro. Es aquí donde el PCB cumple su función más importante:

  1. El planificador (scheduler) decide que el proceso actualmente en ejecución debe dejar la CPU (por ejemplo, se acabó su quantum de tiempo, o el proceso pidió una operación de E/S y debe bloquearse).
  2. El sistema operativo guarda el estado actual del hardware (el valor del PC y de todos los registros de la CPU en ese instante) dentro del PCB de ese proceso. También actualiza su campo de estado (por ejemplo, de "en ejecución" a "bloqueado" o "listo") y lo mueve a la cola correspondiente.
  3. El sistema operativo elige, según el algoritmo de planificación, cuál es el siguiente proceso que va a correr, y carga los registros de la CPU con los valores guardados en el PCB de ese nuevo proceso (incluido su PC), de modo que la CPU continúe exactamente donde ese proceso se había quedado la última vez.
  4. La CPU retoma la ejecución normalmente, sin que el proceso "note" que estuvo pausado.

💡 "Congelar y restaurar" un proceso

Gracias a que el PCB guarda una copia fiel de todo lo que la CPU necesita (PC + registros) más el resto del contexto (memoria, E/S, planificación), el sistema operativo puede "congelar" un proceso en cualquier instante y "descongelarlo" más tarde —incluso mucho después— sin que el proceso pierda absolutamente nada de su progreso. Desde el punto de vista del proceso, es como si nunca hubiera sido interrumpido.

3. Actualización durante la ejecución normal

El PCB también se actualiza en otros momentos, no solo en los cambios de contexto completos: cuando el proceso abre o cierra un archivo, cuando cambia su prioridad (por ejemplo, por envejecimiento en la cola de espera, para evitar inanición), cuando consume más tiempo de CPU (se actualiza su contador de contabilidad), o cuando cambia de estado por cualquier motivo (se bloquea esperando E/S, se desbloquea porque el dispositivo respondió, etc.).

4. Finalización del proceso

Cuando el proceso termina (ya sea porque finalizó normalmente, porque hubo un error, o porque fue cancelado), el sistema operativo:

  1. Actualiza el estado del PCB a "terminado".
  2. Libera los recursos que el proceso tenía asignados: memoria, archivos abiertos, dispositivos, etc.
  3. En muchos sistemas, el PCB (o parte de su información, como el código de salida) se mantiene brevemente disponible para que el proceso padre pueda consultarlo (por ejemplo, para saber si el hijo terminó bien o con error).
  4. Una vez que esa información ya no hace falta, el PCB se elimina definitivamente de la tabla de procesos y su memoria queda libre para ser reutilizada por un futuro proceso.
